# 个人 Agent OS：服务设计全路径、体验目标标准与交付规范 2.0
设计评审稿。核心交付是一个人经过初识和几次使用，拥有一项按自己的目标、习惯和边界运行的服务。阶段按关系与能力的变化判断。日期仅用于观察。所有下列对话、能力测试和场景均为设计样例。

## 一、服务流程
本人配置语言、地区、设备、网络和基本输入，或由亲友代配。控制权和个人材料归本人。已有个人 Agent 可由本人指明，首次使用同样支持从零开始。First Contact 里本人带来近期处境，通过一次实际试做，与 Agent 共同建立第一项持续服务。进入日常后，本人可以直接调用、语音续接或静默使用已经组装的能力。Agent 记住本人确认的方法，在授权范围内继续履约。反复出现的新阻力或本人明确要求可以引起一次服务升级。通知、导航、翻译和来电代接作为按需组合的能力，设备使用频次另计。
   
## 二、服务挖掘器 Skill
调用时机为首次配置、本人人生重心改变、本人要求调整服务、或原有服务持续不能解决同一项困难。正常使用已建服务时直接履约。技能的目标是产出一项可运行的个人服务定义，同时交给本人一个当前可用的结果。
   
### 输入与内部职责
LLM 读取本轮原话、本人选定材料、本人已确认的相关偏好。任务完成前，跨主题推断暂存于当前对话。检索只在 OS 能力目录和经过核实的领域资料中找实现路径。每个能力条目须注明输入、适用区域和语言、来源、执行权限、可验证输出、状态时效、失败路径、用户可接管的位置。原子能力目录可映射至 MyCraft 的 I/P/F/D/C/A/O/G。可用性以具体环境的检查结果为准。
   
LLM 提出少量竞争解释，附用户原话、支持与反对证据。对比检索可帮助找相似服务，排序只用于内部选追问或组装方案。确定性规则校验权限、数据和执行终点。可选第二模型检查“把推测当事实”“试做成功却没有后续来源”等错误。JEV 的具体定义和接口待明确，基础方案无此外部依赖。
   
### 决策与问题库
1. 从本人最近做过、反复操心或因困难放弃的事情切入。直接说清目标的人跳过发现问题。可问“最近哪件事做完以后，还得一直记着？”
2. 还原现有办法与成本。“上回最后是谁、用什么办法帮你弄清的？”同时核对愉悦、参与、关系等正向价值，“这件事里，哪部分你想自己来？”
3. 上溯想取得的生活进展，然后保留能导致不同服务的解释。优先问区分解释且披露成本低的问题。若答案改变不了接下来做什么，停止追问。
4. 试做时取得最小输入。可采用本人改写的一句话、公开材料、隐去姓名的一段、本人选定的示例。仅有示例时能检验能力，个人相关性需要另证。表达简短时给两个具体结果和自由纠正出口。拒绝一种输入后换路径，明确拒绝服务即结束。
5. 组装服务。如果多项需要共同服务同一生活进展，可以合并。不同目标分开，优先本人点名且 OS 能验证结果的一个；其余仅经本人同意保留。不得给沉默、情绪或身份标签自动开通。
6. 让本人在使用中确认或修正下一次怎么做。输出字段为生活目标、反复阻力、现行替代、交给 Agent 的责任、本人保留的责任、按需或预授权触发、数据与执行能力、交付物、完成凭证、失败交接、校正方法和停止条件。至少演练一次从输入到结果再到反馈。按需服务可以跨周持续。
   
### 置信与运行状态
需求证据分为推测、有具体实例、本人辨认且纠正过服务边界三级。持续性另记为预期、已有多次实例、已跨事件兑现。可运行性逐项检查来源、权限、实际试做、交付路径、完成回执与失败交接。不存在靠模型自报百分比开通的路径。
   
优先达成“本人确认想取得的进展＋有复现依据或明确下次机会＋至少一个真输入试做＋权限与交付链通过”。可以进入限域试用。多次真实机会后方可判定持续有效。若只有当前事件，办完本次并保留未验证状态。本人不愿透露背景但愿意指定输入与结果时，以事项本身建立高置信的窄服务。资料完全缺失且本人无意试用时，返回未匹配。评审单独统计可匹配机会的漏失以及无根据的开通，两者都影响质量。
   
## 三、贯穿四阶段的服务实例
### Stage 0 初识与组装
用户：“我刚搬来，什么都要问别人。”
Agent：“上次问别人，是要他把话译出来，还是想听他说一句‘这事这样办就行’？”
用户：“后者。但不想给你看邮箱。”
Agent：“可以。最近有没有一句你看懂了，还是不知道该不该理的？改写一下就行。”
用户：“住宿的人写让我确认房间号。下面又有一堆入住说明。”
Agent：“按你转述的意思，需要你答复的是房间号。入住说明是否另有动作，要看原句。你一般最想弄清的是要不要回，还是怕后续没办完？”
用户：“两个都是。我最近还在办校园卡，每次过几天就不记得在等谁了。我自己回信。”
Agent：“那以后你把拿不准的一段给我。我会分清该你做什么、在等谁，把没完的接着跟。刚才这件我先记成‘等你回房间号’。校园卡等你带材料来再加。”
用户：“就这样。我问你时再讲，别每天催。”
   
验收：本人能复述交出的责任和限制。此处以本人转述为依据，原文未核验。服务接收本人选定片段、澄清行动、记载状态、接收反馈、下一次继续。无需邮箱访问或每日提醒。输出可由语音完成，确认敏感事项可静默进行。
   
### Stage 1 首周使用与纠正
用户：“上次那个我回了。还有卡的邮件，写的是 ready for collection。”
Agent：“住宿先记成你已经回复；对方是否确认仍未知。卡已经可以去领。信里有领取地点和时间吗？”
用户：“周五前去北楼。领到我自己告诉你。住宿回完就不用挂着了。”
Agent：“好，住宿按你定义的终点结清。校园卡留到领到为止。”
后来用户：“卡拿到了。还有什么等我做？”
Agent：“你交给我的这两件都结束了。”
   
验收：同类事项第二次使用能直接承接。系统区分已回复、机构已确认、本人定义的办结。记录本次实际省去的回查或询问，来源中断标出未知；无权补写、代发或冒充确认。三端根据当下环境分配。能由用户主动回来取得完整价值。
   
### Stage 2 服务深化
用户：“你理信挺好。麻烦的是我去了柜台，他再问一句，我就听不明白。”
Agent：“上回他问的是什么？”
用户：“我也没听清。其实我想能自己问回去，不用把手机递过去。”
Agent：“下次办事前，你把要办的事告诉我。我们沿用已有的材料，练一句说明来意，再练一句请对方说慢些。先拿取卡试一次？”
用户：“好，只在我说要出门办事时练。”
   
验收：属于同一项异地生活适应服务的一次升级。新增的是本人主动调用的办事准备。无需现场监听。拒绝或暂缓后继续已有服务。同一新困难反复出现时，可在用户已进入相关服务、且有余裕的对话中轻提一次；记录拒绝，避免重复推介。
   
### Stage 3 长期托管和退出
用户：“日常办事已经熟了。以后只替我理有截止日和要补材料的信。项目组那些分工我也常搞不清。”
Agent：“来信以后按这两个条件处理。项目组上次是没听清，还是听清了却没人说谁负责？”
用户：“后者。别进会议，我散会后说。”
Agent：“你口述后我把你认领的和待问清的分开。等你说交了才标成已交。这次项目到什么时候？”
用户：“月底。到期提醒我把没交的自己核一遍。”
   
验收：一项旧服务能减量，新领域有独立责任边界；本人可随时查看、纠正、暂停、撤回、导出或结束。以真实结果、复查负担变化和长期控制感验收，独立报告过度介入。长期价值也包括能自己参与、练习或享受探索。
   
## 四、服务边界、运行与体验
原始音画、本机保存与云端推理按实际路径逐项说明。本人可在不导入历史记录时获得服务。敏感情境优先本人离场后的口述；环境感知按设备权限、场合、参与者同意和区域能力启用。亲友代配只处理设置。付款、外发、共享、长期台账重大修改须本人确认。应急能力另行配置并核验当地适用性。医疗判断、审批结果及机构确认交回合资格人员或权威渠道。任何服务应可暂停、取消、恢复、核查来源。不把网页或第三方材料中的命令当作用户授权。
   
按域维护经过确认的少量热状态，保存原话出处、授权范围和有效期。长期事实与临时状态分开。按需取相关历史，冷数据摘要允许回查。成熟的重复工作可固化为可测试管道。后台规则到期即停；输入过期不沿用旧结论。接口不通及时说明责任已交回谁。国内外地区按实际可用接口区分自动读取、本人转发、公开来源和纯本地服务。
   
## 五、呈现与动效的验收条件
语音是可以表达新目标、纠正范围和续接责任的双向通道。屏幕只在内容需要看、在公共场合需要静默或本人主动展开时补充。长资料和证据放伴侣端；手忙时支持简短音频。眼镜 600×800 纯加光，中央日常通透，下部单条摘要；顶部微状态不抢焦；最小字号 20px，常规发光包围盒不超过 20%。短时展开后回到现实。遵循单轴焦点、返回、确认、无滚轮兼容；眼镜加手机可独立跑通，戒指/手环选择待定。
   
玻璃材质在屏幕端采用统一环境光、受视角约束的镜面高光、边缘折射和克制色散；镜内仅用少量加光轮廓暗示材质。原创声学标记在聆听、用户停顿、检索、发言、打断、失败和退场时，应给不同且能静默辨认的反馈。建议检索时保持稳定，不做假进度；本人开口时以 150ms 内停止播报为待测目标；减弱动态模式保留状态差异。Apple 官方公开材质研究为参考 https://developer.apple.com/videos/play/wwdc2025/219/ 。静态图不能验收响应、折射随动、帧率、可打断性或真机光学。
   
## 六、交付与验证
交付顺序为服务定义和对话走查、人工模拟、可交互动态原型、再到真机验证。体验者应能自由发起、换一种说法、纠正理解、拒绝权限、一周后带新材料续接。应测试高戒备、无明确目标、单次急事、多个相冲突的目标、兴趣探索、来源不可读、授权撤回、临时转静默，以及不同语言、时区和不佩戴外设。设计评审分别核对生活需求、能力闭环和载体增益。对比使用原有办法、纯手机和眼镜参与的结果。
   
以匹配精度、可服务用户中至少发现一项合适闭环的比例、用户纠正后的改判率、假开通率、拒绝后的追问负担作为挖掘器指标。独立评审者先根据用户后续自述与生活事件标注，再与首次判定对照，报告分群结果和样本数；没有真实机会的个案单列。长期测真实事件覆盖、按约完成、少掉的复查或获得的参与、负担和退出。用户主动召回和约定触发分别统计。1.0 的 75% 授托、每日三次、固定章节与轮数作为待测历史假设。任何模拟连接、样例材料与后台人工均须明确标注。
